## 1. Project overview

Primal Ruin is a two-player strategic card game prototype (prehistoric/fantasy theme) with a
pixel-art styled browser interface. It implements an incremental subset of a "Core 1.0" ruleset:
setup, opening hand + Mulligan, two starter Domains, turn phases, drawing, a hand limit, Unit
deployment across three Fronts, combat, human sacrifice, several keywords, a (provisional) Commander
system with Rifornimento and once-per-turn abilities, and a basic automatic opponent.

The project deliberately separates three concerns:

- **Data** — the card catalog generated from `Set.txt`.
- **Rules** — small, deterministic, dependency-free modules under `src/`.
- **Engine + presentation** — the stateful modules in `src/engine/` (re-exported by `game.js`) and the DOM UI modules.

Goals (from `DialogoAi.md`): evolve the prototype toward a faithful Core 1.0 implementation, keep
card data separate from game logic, implement features incrementally and verifiably, and never
declare a rule complete until it is implemented and tested.

## 4. High-level architecture

The application is a **single-page, single-`GameState`-singleton** architecture with a strict
top-down dependency direction: UI/engine → rules → data.

```
                       ┌──────────────────────────────┐
                       │        index.html             │
                       │  markup: board, controls,     │
                       │  archive, deck-builder        │
                       └───────────────┬───────────────┘
                                       │ <script type="module" src="/src/main.js">
                       ┌───────────────▼───────────────┐
                       │           src/main.js         │ entry point
                       │  DOM event wiring, keys, boot │
                       └───┬───────────┬───────────┬───┘
             ┌─────────────┘           │           └──────────────┐
             ▼                         ▼                          ▼
   ┌───────────────────┐    ┌───────────────────┐      ┌───────────────────┐
   │  src/card-library │    │  src/deck-builder │      │   src/settings    │
   │   (archive UI)    │    │   (builder UI)    │      │  (preferences)    │
   └─────────┬─────────┘    └─────────┬─────────┘      └───────────────────┘
             │                        │
             │                        ▼
             │              ┌───────────────────┐
             │              │ src/deck-validation│
             │              └───────────────────┘
             ▼
   ┌───────────────────────────────────────────────────────────────────────┐
   │                         src/engine/                                    │
   │  state · combat · renderer · controller-* · cards · logger · fx        │
   │  game.js re-exports GameController and GameState only                  │
   └───┬─────────┬──────────┬──────────┬──────────┬──────────┬─────────────┘
       │         │          │          │          │          │
       ▼         ▼          ▼          ▼          ▼          ▼
 card-effects tactics  permanent-  game-     card-costs  unit-triggers
                        effects     rules
       │         │                   
       └────┬────┘   (pure rule modules; no DOM, no imports back into game.js)
            ▼
   ┌────────────────────┐   ┌──────────────┐  ┌───────────────┐
   │ src/data/cards.json│   │ src/random.js│  │src/save-store │ src/pixel-art
   │  (360 cards)       │   │ src/settings │  │ src/pixel-art │
   └────────────────────┘   └──────────────┘  └───────────────┘
```

Key architectural properties:

- **Single mutable state object.** `GameState` in `src/engine/state.js` holds all match state. Rule
  modules receive state as arguments and return values; they do not import `game.js` or `src/engine/`,
  so there is no cycle between rules and the engine. The engine modules do import each other.
- **Two "actor" model.** `GameState.players[0]` is always the human; `players[1]` is the automated
  opponent. `currentIndex` toggles who is active via the `current`/`opponent` getters.
- **Two-sided resolution.** Human actions run through `GameController` methods (driven by DOM
  events). Enemy actions are driven by `GameController.runEnemyTurn()`, which reuses the same rule
  modules and (partly) the same controller methods.
- **Camera-agnostic combat.** `CombatResolver.resolveFront` uses `GameState.current` as attacker,
  so it works for both the human turn and the scripted enemy turn.
- **Persistence checkpointing.** `UIRenderer.refresh()` triggers `persistGame(GameState.snapshot())`
  except while an interactive prompt is pending (so pending choices are not serialized).

## 5. Module reference

### 5.1 `src/main.js` — application entry point

Boots the game and wires all DOM interactions. It is the only place that binds HTML controls to
`GameController` methods.

- Imports `../styles.css`, `GameController` from `../game.js`, and the UI initializers
  `initCardLibrary`, `initDeckBuilder`, `initSettings`.
- Registers click handlers for every control button (Mulligan, start, main phase, combat, channel,
  end turn, sorvolo, torment, tactic confirm/cancel, new game, demo decks).
- Registers click + keyboard (`Enter`/`Space`) handlers for all 9 player board slots
  (`p-{left|center|right}-{line|supA|supB}`) → `GameController.handleSlotClick`.
- Calls `GameController.init()` at the end.
- Adds global shortcuts: `Esc` = cancel selection, `Enter` = start game, `Space` = advance phase
  (main → combat → end turn), ignoring events originating from form controls.

### 5.2 `src/random.js` — deterministic PRNG

A saved-state xorshift32 PRNG so a reloaded game resumes the identical random sequence.

| Export | Purpose |
|---|---|
| `seedRandom(seed)` | Validates and sets a 32-bit unsigned seed (0 is coerced to 1). Throws `RangeError` otherwise. |
| `nextRandom()` | Advances state, returns a float in `[0, 1)`. |
| `getRandomState()` | Current 32-bit state (stored in saves). |
| `restoreRandomState(savedState)` | Restores state via `seedRandom`. |

### 5.3 `src/game-rules.js` — pure combat / deployment rules

No DOM, no sibling imports — highly unit-testable.

- `calculateUnitCombatStrength({line, supportCount, supportBonusPerUnit, supportBonusCap, collectiveCount, fewerUnits, logorare, ferocityBonus})` — computes a Line's effective strength: base `currentForce` + capped support bonus + Mente Collettiva bonus (capped at +3) + Ferocia bonus − Logorare penalty, floored at 0.
- `compareCombatStrengths(left, right)` — returns `{result: 'tie'|'left-wins'|'right-wins', margin}`.
- `shouldUseTorment({commanderPc, madness, commanderDamage, torment})` — deterministic Torment choice for the AI (prefers the outcome with greater relative progress toward victory).
- `checkDeployment(unit, front, slotName, {ownSites, opposingSites})` — deployment legality, including Line-restricting sites (`set-1-105`, `set-2-094`), Assalto Line-swap, and Posizione Difensiva constraints. Returns `{legal, assaultSwap}`.

### 5.4 `src/card-costs.js` — pure cost calculation

- `calculateCardCost(player, card, {fromDiscard, turnNumber, players})` — base cost; adds `equipCost` for Equipment; applies Eco Spettrale discounts (`set-2-081`, `set-2-114`, `set-2-096` once-per-turn) and the from-discard surcharge; applies Velo del Silenzio (`set-2-117`) style cost increases for 1-cost tactics under opponent conditions; floors at 1.
- `markCardCostDiscountUsed(player, card, turnNumber, fromDiscard)` — marks the once-per-turn site discount (`set-2-096`) as consumed **only if** it actually reduced the payment.

### 5.5 `src/card-effects.js` — effect registries & execution status

The declarative "what does the engine actually support" layer, and the bridge to `tactics.js`.

- **Registry sets** (IDs checked against the catalog by tests): `registeredEquipmentIds` (28),
  `registeredSiteIds` (70), `registeredFieldIds` (26), `registeredUnitEffectIds` (65).
- `IMMEDIATE_TACTICS` (6): tactics resolved inline without a target prompt.
- `applyTemporaryForce` / `restoreTemporaryForce` — apply/revert until-end-of-combat force changes, tracking `temporaryForce` and `forceLostThisTurn`.
- `isImmediateTacticSupported(card)` / `resolveImmediateTactic(card, player, opponent, choice, context)` — dispatch a tactic to a registered resolver or an inline immediate effect.
- `getTacticChoices(card, player, opponent)` — legal target choices (delegates to `tactics.js`, with extra filtering for some fields, e.g. `set-2-091`).
- `getCardExecutionStatus(card)` → `{label, detail}` — one of `Unità base`, `Keyword implementata`,
  `Implementata`, `Parziale`, `Non eseguibile`. Used by the archive, deck builder, and the coverage
  script (see [§11](#11-testing--tooling)).

### 5.6 `src/tactics.js` — Tactic resolvers (large module)

Holds the tactic system: two ID sets — `IMPLEMENTED_TACTICS` (62) and `TACTICS_REQUIRING_CHOICE`
(many of them) — plus pure helpers (`lineChoices`, `supportChoices`) and:

- `isRegisteredTactic(card)` / `tacticRequiresChoice(card)`.
- `getTacticChoices(card, player, opponent)` — builds the legal-choice list per tactic ID.
- `resolveRegisteredTactic(card, choice, player, opponent, context)` — applies the chosen effect; receives injected `context` callbacks (`damageLine`, `onForceLoss`, `removeUnit`, `destroyUnit`) so it can stay free of `game.js` imports.
- `registeredTacticIds` — frozen array of implemented IDs.
- `restoreControlledUnits(players)` — reverts temporarily-controlled units to their owners (used at combat end).

### 5.7 `src/permanent-effects.js` — permanent/keyword computation

Computes the derived characteristics of Units and permanents (Sites/Fields/Equipment). All pure.

- `getUnitKeywords(player, unit, frontName, slotName)` — unit keywords plus keyword grants from Equipment, Sites and Fields (e.g. Ferocia from `set-1-100`, extra Logorare from `set-2-104`).
- `getUnitForceBonus(player, unit, frontName, slotName, opponent)` — a long ordered list of conditional force bonuses from equipment, sites, fields, adjacency and opposing permanents.
- `getFerocityBonus(...)` — Ferocia value (1 or 2) when the player controls fewer units.
- `getDamageReduction(player, unit, frontName, slotName)` — damage shield/reduction from equipment and sites.
- `getSupportBonus(player, frontName)` — support bonus capped at 3, including enhancers/sites.
- `countUnits(player)` / `playerUnits(player)` — occupancy helpers.
- `createToken(owner, frontName, slotName, name, force)` — creates a "Pedina Sciame"/"Pedina Raptor" token in a slot.

### 5.8 `src/unit-triggers.js` — Unit trigger tables

Declarative tables mapping specific card IDs to trigger effects, consumed by `game.js`.

- `getUnitLineDestructionEffects(line)` — effects printed on the attacker's Line when a combat-destroy occurs (extra commander damage, draw, parasite, exile, temporary force).
- `getUnitEntryEffects(unit)` — on-entry effects (recover from discard, add parasites, create tokens, destroy enemy support).
- `getSorvoloEntryEffects(unit)` — Sorvolo-entry effects.
- `getUnitDestructionReactions(units, destroyedUnit, turnNumber)` — reactions of surviving units to a destroyed unit (with once-per-turn guards).
- `hasSeminatoreSilente(units)` — whether `set-3-050` is in play.

### 5.9 `src/deck-validation.js` — pure deck validation

- `validateDeckIds(cardIds, knownCardIds)` → `{valid, message}`. Enforces exactly 40 cards and all
  IDs known; deliberately imposes **no copy limit**.

### 5.10 `src/deck-builder.js` — deck builder UI

- `validateDeck(cardIds)` — thin wrapper over `validateDeckIds` using the catalog map.
- `loadCustomDeck()` / `saveCustomDeck(cardIds)` / `clearCustomDeck()` — persist the 40-card deck list under `primal-ruin.custom-deck.v1`, validating on load/save.
- `initDeckBuilder(onUseDeck)` — renders the catalog list and the current deck, supports add/remove, shows validation and unsupported-card warnings, and calls `onUseDeck(cardIds)` (wired in `main.js` to `GameController.resetWithDeck`).

### 5.11 `src/card-library.js` — card archive UI

- `initCardLibrary()` — filters the catalog by set / category / free-text query, renders cards into
  `#catalog-grid`, and shows each card's engine execution status via `getCardExecutionStatus`.

### 5.12 `src/settings.js` — preferences

- `getSettings()` — current `{audio, animationSpeed}`.
- `initSettings()` — reads/validates `primal-ruin.settings.v1` from `localStorage`, wires the audio
  toggle and animation-speed select, and updates the CSS variable `--animation-duration`
  (`animationSpeed * 180ms`).

### 5.13 `src/save-store.js` — game persistence

Versioned save (`primal-ruin.game-save.v1`, `SAVE_VERSION = 3`).

- `persistGame(snapshot)` — writes `{version, savedAt, snapshot}` and updates the status line.
- `loadGameSave()` — parses and **strictly validates** the snapshot shape (2 players, PC/Follia/Echo ranges, deck/hand/discard arrays, 3 valid fronts, phase enum, turn/player indices, `randomState` range) before returning it; returns `null` (and logs) on any incompatibility.
- `clearGameSave()` — removes the save.

### 5.14 `src/pixel-art.js` — procedural card art

- `drawCardPixelArt(canvas, card)` — draws a deterministic pixel-art illustration based on a
  hash of the card id and a per-set palette (`PALETTES`). Placeholder art, not final assets.

### 5.15 `src/commanders.js` — Comandanti (provisional roster + pure evaluation)

Introduces the **Commander** system from the official ruleset: every Commander has a
**Rifornimento** ability and a **once-per-turn activatable** ability. The rules define the slots
but not yet their content, so the roster is **provisional** (`provisional: true`, shown as
`(provvisorio)` in the UI) and is intended to be replaced with final data. Pure module — no DOM, no
`game.js` import.

- `COMMANDERS` — the provisional roster: `cmd-1-01` *Arconte delle Ossa* (set-1, PC 20),
  `cmd-2-01` *Signore delle Fiamme* (set-2, PC 18), `cmd-3-01` *Veggente Silente* (set-3, PC 20).
  Each entry has `id`, `name`, `setId`, `pc`, `provisional`, and two abilities (`rifornimento`,
  `activation`) described by a list of `ops`.
- Recognised ops: `gainEcho {amount}`, `addMadness {target, amount}`, `addParasite {target, amount}`,
  `drawArmy {amount}`. Recognised condition: `madnessAtMost {value}`.
- `listCommanders()` — public metadata only (`id, name, setId, pc, provisional`).
- `getCommander(id)` / `defaultCommanderId()` / `commanderForSet(setId)` — lookup, first-roster
  default, and per-set resolution with fallback to the first Commander.
- `evaluateCommanderAbility(ability, {self})` — **pure**: returns `{ok, reason, effects}` where
  `effects` is a list of `{kind, target, amount}` descriptors; defaults the target to `self` for
  self-ops and `opponent` otherwise; never mutates the actor.
- `validateCommander(commander)` — returns a list of data problems (missing id/name/pc, unknown op
  or condition, empty ops).

`game.js` interprets the returned `effects` through `GameController.applyCommanderEffects`.

## 6. Engine deep dive (`src/engine/`)

`game.js` is a facade. It re-exports `GameController` and `GameState` so `index.html` / `src/main.js`
and the tests keep importing `../game.js`. The implementation lives in `src/engine/`. Open only the
file for the behavior you are changing:

| File | Open it for |
|---|---|
| `src/engine/state.js` | `GameState`: match state, setup, snapshot, victory, turn-start and combat-start permanents, unit entry and movement |
| `src/engine/combat.js` | `CombatResolver`: strength, combat, Torment, sacrifice, destruction, promotion |
| `src/engine/renderer.js` | `UIRenderer`: board, hand, controls, prompts |
| `src/engine/controller-match.js` | match lifecycle, mulligan, turn boundaries, slot clicks, prompt dismissal |
| `src/engine/controller-play.js` | playing units, sites, fields, equipment, discard selection |
| `src/engine/controller-tactics.js` | the human tactic flow |
| `src/engine/controller-combat.js` | combat phase, Sorvolo, bonus cleanup, enemy turn |
| `src/engine/controller-commander.js` | Commander abilities |
| `src/engine/controller.js` | assembles `GameController` from the `controller-*` method groups |
| `src/engine/cards.js` | deck, card-instance and player factories |
| `src/engine/board.js` | front/slot names and catalog aliases |
| `src/engine/tactic-choices.js` | tactic-choice filter |
| `src/engine/logger.js` | `Logger` |
| `src/engine/fx.js` | `FX` audio |

The five collaborating singletons are unchanged: `GameState`, `Logger`, `FX`, `UIRenderer`,
`CombatResolver`, plus `GameController`. Factory helpers live in `src/engine/cards.js`.

### Factory helpers

- `makeUnit(card, id, owner)` / `makeCardInstance(card, id, owner)` — build runtime card instances
  from catalog entries, extracting keywords from `rulesText` via `KEYWORD_PATTERNS`.
- `makeDeck(owner, setId, customCardIds)` — builds a shuffled 40-card army deck (custom list or 40
  random Units of a set).
- `makeDomainDeck(owner)` — 20 shuffled Domains.
- `makePlayer(id, setId, customCardIds, commanderId)` — the full player object (see
  [§7](#7-data-model)); resolves `commanderId` (falling back to `defaultCommanderId()`) and takes the
  Commander's `name` and `pc`.
- `shuffled(items)` — Fisher–Yates using the shared PRNG; `extractKeywords`, `cardIcon`.

### `GameState` — the single source of truth

Holds `players`, `currentIndex`, `phase`, `turnNumber`, `firstPlayerIndex`, `firstTurn`,
`mulliganUsed`, selection fields (`selectedCard`, `selectedFromDiscard`), `gameOver`, and pending
interaction slots (`sacrifice`, `pendingTactic`, `pendingTorment`, `pendingPromotion`, `pendingSorvolo`, `sorvoloUsed`).

| Member | Role |
|---|---|
| `get current` / `get opponent` | Active player and the other one (by `currentIndex`). |
| `reset(customDeckIds)` | Seeds the PRNG from `crypto`, builds both players, draws 5 cards + 2 domains each, randomly picks `firstPlayerIndex`, resets all transient state and logs the setup. |
| `onUnitEntry(...)` | Central "unit entered play" hook: equipment position triggers, collective entry bonus, entry effects, Infiltrazione/site parasites, site-driven moves, `set-1-092` self-destruct. |
| `applyCollectiveEntryBonus(...)` | `set-3-049` scaling bonus. |
| `triggerSiteSupportMove` / `resolveSiteSupportMove` | Portale Silente (`set-3-097`) support movement (human prompt vs. AI auto-choice). |
| `addParasites(source, target, count)` | Adds Parassiti and resolves their site/field side effects; checks victory. |
| `resolveSiteActivation(site, choice)` | Executes activatable sites (`set-1-102`, `set-2-088`, `set-3-082`, `set-3-089`). |
| `snapshot()` / `restore(snapshot)` | Serialize/deserialize the persistable core (players + turn scalars + PRNG state). |
| `countUnits` / `unitsInFront` | Occupancy helpers. |
| `checkVictory()` | Ends the game on `pc <= 0` / `follia >= 10` (simultaneous defeat: the turn player wins), or on Total Map Dominance (turn player holds a Line in all 3 Fronts and the opponent has no Units); logs, shows the result, persists. |

### `Logger`

Appends `> message` lines to `#log`, caps the log at 100 entries, auto-scrolls, and supports a
`ferocity` color style.

### `FX`

Minimal Web Audio wrapper: `tone(freq, type, duration)` and `play(kind)` for `draw` / `play` /
`attack` cues, gated by `getSettings().audio`.

### `UIRenderer` — DOM projection of state

Reads `GameState` and renders; contains **no** rule logic beyond display.

- `updateStats()` — commander stats (PC/Follia/Echo/Parassiti/deck/domains); also calls
  `renderCommander()`.
- `renderCommander()` — fills the player/opponent Commander name and ability text, and whether the
  activatable ability is still "pronta" or "già usata".
- `renderDomains(player, containerId)` — domains + sites + field; makes activatable sites focusable/clickable.
- `renderSlot(prefix, frontName, slotName, unit)` — a single board slot (icon, name, keywords, `currentForce/force`).
- `renderBoard()` — all slots + domains + stats + controls + interactivity.
- `renderHand()` — hand cards and the "Eco Spettrale" playable-from-discard cards; disables cards that cannot be played.
- `updateBoardInteractivity()` — marks legal deployment slots using `checkDeployment`.
- `resolvePermanentTurnStart(playerIndex)` — resolves all `turn-start` site/field effects (decay, tokens, forced moves, draws, force loss, etc.).
- `resolvePermanentCombatStart(playerIndex)` — resolves combat-start site/field effects.
- `applyTemporaryForce` / `applyForceLoss` — adjust Line force with logging and cascade to `CombatResolver`.
- `onUnitMoved(...)` — the cousin of `onUnitEntry` for moves (Sorvolo, site moves), including `set-3-117` and equipment interactions.
- `resolveSorvoloEntryEffects(...)`.
- `renderControls()` — shows/hides the correct action buttons per phase and populates the tactic/torment/promotion/sorvolo prompt panels; disables `#player-commander-select` outside setup and toggles the Commander button (`#btn-commander`: visible only in the human main phase, disabled once used or while a prompt is pending).
- `showGameOver(winner)` / `refresh()` — refresh re-renders board+hand and persists (unless a prompt is pending / mid-combat).
- `getSorvoloOptions()` — enumerates legal Sorvolo moves.

### `CombatResolver` — combat and destruction

- `resolveAll()` — iterates fronts left → center → right, then checks victory.
- `strength(player, frontName, enemyLine)` — builds the effective Line (adding permanent force bonuses and resolved keywords) and calls `calculateUnitCombatStrength`.
- `commanderDamage(winner, loser, frontName, margin)` — margin plus tactic/field/site bonuses (breakthrough, collective overrun, double central damage, etc.).
- `resolveFront(frontName)` — the heart of combat: handles both-empty, exposed-front loops, ties, winner/loser determination, Torment, commander damage, and Line damage.
- `chooseTorment(...)` / `chooseTormentOutcome(...)` — Torment decision (AI deterministic, human prompted via a Promise).
- `promptPromotionSlot(...)` / `choosePromotionSlot(...)` — when the human Line is destroyed with two Supports, the player chooses which one is promoted (`defaultPromotionSlot` in `game-rules.js` resolves the AI's deterministic choice).
- `dealCommanderDamage(defender, frontName, amount)` — AI pre-sacrifice logic; human sacrifice prompt via `GameState.sacrifice` + Promise.
- `removeUnit(...)` / `destroyUnit(...)` — remove with zone routing (Divinità → discard "Sigillata", Eco Spettrale → exile, else discard), promotion of Support to Line (explicit slot or `defaultPromotionSlot`), and `set-1-117` penalties.
- `onUnitRemoved(...)` — the large destruction-trigger dispatcher (site/field/equipment reactions, unit destruction reactions, Line-destruction effects, control transfers).
- `onForceLoss(...)` — force-loss triggers (Eco del Dolore draw, `set-2-110` reflect, `set-2-118` field damage, `set-2-098` destroy).
- `restoreControlledUnits()` / `promoteSupport(...)` / `damageLine(...)` / `sacrifice(...)` / `finishSacrifice()`.

## 8. Game flow

### Phases

`setup → rifornimento → principale → scontro → finale → (next player's rifornimento) → … → gameover`

Phase labels shown in the UI: `PREPARAZIONE`, `RIFORNIMENTO`, `FASE PRINCIPALE`, `SCONTRO`,
`FASE FINALE`, `PARTITA TERMINATA` (`UIRenderer.renderControls` in `src/engine/renderer.js`).

### Turn lifecycle

`GameController.beginTurn(playerIndex)`:

1. Increment `turnNumber`, set phase to `rifornimento`.
2. Reset per-turn flags (commander ability, tactics played, front wins, per-slot damage/force-lost),
   then resolve the Commander's **Rifornimento** ability (`resolveCommanderRifornimento`).
3. Untap the player's Domains.
4. `UIRenderer.resolvePermanentTurnStart(playerIndex)` — decay, `set-1-110` forced sacrifice, tokens, forced moves, site/field effects.
5. Parasite maintenance (loss of PC; remove one if ≥ 3; Seminatore Silente extra loss).
6. If the enemy (index 1), auto-channel Follia → Echo.
7. Draw one Domain; draw one Army card (except the very first turn of the first player).
8. For the human, phase stays `rifornimento`; for the enemy, phase becomes `principale` and `runEnemyTurn()` executes immediately, then `beginTurn(0)` is called for the human.

Human turn: `rifornimento` → (optionally channel madness) → `enterMainPhase` → `principale`
(play cards / activate sites) → `resolveCombat` → `scontro` → `finale` → `endTurn` (discard to 7,
clear Echo) → `beginTurn(1)`.

### Combat resolution

`CombatResolver.resolveFront(frontName)` per front (left → center → right):

- No attacker Line and no defender Line → nothing.
- Attacker Line absent, defender Line present → defender "wins" the empty front and the attacker takes full defender strength as commander damage.
- Attacker Line present, no defender Line → attacker deals its strength as commander damage.
- Both present → compare strengths:
  - **Tie**: both Lines take 1 damage.
  - **Winner** deals `margin + bonuses` commander damage (or Torment if the winning Line has Torment).
  - **Loser's Line** takes `margin` damage; if destroyed, the Support promoted to Line is chosen by the
    player when they have two Supports (human prompt / `defaultPromotionSlot` for the AI), and the excess continues.
- Commander damage may be prevented by sacrificing units (`dealCommanderDamage`; human is prompted, AI decides by heuristic).

At combat start `UIRenderer.resolvePermanentCombatStart` fires; at combat end `removeCombatBonuses`
reverts temporary force/keywords, restores controlled units, clears leftover zero-force units, and
clears `tacticEffects`.

### Enemy AI

`runEnemyTurn()` loops: it filters hand to playable cards (units and supported tactics, respecting
tactic limits, cost, and Echo), scores each candidate via `scoreEnemyPlay` (force/cost ratio plus
keyword weights and slot heuristics) or a flat tactic score, sorts deterministically, and plays the
best. At the start of its turn it also fires the enemy Commander's activatable ability when ready.
After deploying all it can, it runs the same `CombatResolver.resolveAll()` and ends in `finale`.

## 12. Known limitations & current status

The code is an **incremental prototype**, not a complete Core 1.0 simulation. Documented divergences
and gaps:

- **Commanders are provisional.** The Commander system is implemented end-to-end (a Rifornimento
  ability, a once-per-turn activatable ability, per-player selection, engine + AI + UI integration,
  save schema v3), but the official roster content is not defined yet: `src/commanders.js` ships a
  3-entry **provisional** roster (`provisional: true`, shown as `(provvisorio)` in the UI) meant to be
  replaced with final data.
- **Unit abilities are partial.** 65 unit effects are registered; according to coverage, **68 units
  are still `Parziale`** (free-text abilities not fully executed). Free-text abilities are generally
  not transpiled into executable effects; unsupported effects are explicitly flagged rather than
  guessed.
- **Optional permanent abilities.** Some optional Site/Field/Equipment choices use a
  **deterministic automatic resolution** instead of an interactive prompt. These operational
  assumptions are documented but do not replace canonical data.
- **Portale Silente (`set-3-097`).** The card text does not specify the destination of the moved
  enemy Support; the prototype offers a free adjacent Support slot — an explicit temporary
  interpretation.
- **Torment.** Presented to the human as a Follia-vs-damage choice; the AI chooses deterministically
  by relative progress toward victory.
- **Support → Line promotion.** When the human Line is destroyed with two Supports the choice is
  interactive; the AI uses the deterministic `defaultPromotionSlot`. The prompt is fully awaited only
  in the combat path (`resolveFront`); effect-driven Line destruction routed through synchronous AI
  dispatchers (`onUnitRemoved`, Sorvolo entry, tactic callbacks) resolves the prompt asynchronously.
- **Deck builder.** Validates exactly 40 cards but imposes **no copy limit** (none is specified in
  Core 1.0); it allows currently-unplayable cards and warns about them.
- **Demo decks.** Without a custom deck, a game uses 40 **random, unbalanced** Units of the selected
  set.
- **Persistence is local.** Saves/decks/settings live in the browser `localStorage`; not synced or
  exportable as a backup.
- **AI.** The automatic opponent is basic and heuristic; combat rules do not yet have full test
  coverage.
- **Art & audio are placeholders.** Card illustrations are procedural pixel art drawn on Canvas;
  audio is synthesized oscillator tones. No final assets.
- **Rule attribution.** Where a card contradicts a general rule, the card text wins; effects resolve
  in play order. Unverified interactions should be treated as incomplete.
